# SQL 운영 점검 (DuckDB)

고정된 최종 12주 결과를 SQL로 다시 계산하고 Python 산출물과 대조한다. 새로운 성능 실험이 아니며, 모델·예측·판단 규칙을 바꾸지 않는다.

## 실행

```bash
pip install -r requirements.txt
python 12_sql_monitoring.py          # 결과: sql_monitoring/ (이미 있으면 덮어쓰지 않음)
```

종료 코드는 대조가 모두 일치하면 `0`, 하나라도 다르면 `1`이다.

## 구성

| 파일 | 내용 |
|---|---|
| `sql/01_source_checks.sql` | 정제 전 원천 전체(10개 매장) 점검 |
| `sql/02_forecast_monitoring.sql` | 고정 평가 키 기준 예측 점검과 지표 |
| `12_sql_monitoring.py` | DuckDB 실행, Python 산출물과 대조, 기록 저장 |

## 1. 원천 점검

| 점검 | 구분 | 처리 |
|---|---|---|
| 날짜 문자열과 연·월·일 불일치 | 오류 | 매장·날짜 묶음과 행 수 |
| 일요일이 아닌 날짜 | 오류 | 문자열·연월일 기준 각각 |
| 매장×상품코드×주 키 중복 | 오류 | Date 문자열 기준 |
| 매장별 주 달력 누락 | 오류 | 고정 52주 달력(2012-04-01~2013-03-24) 대비 |
| 음수 판매수량 | 검토 후보 | 이유 미확인, 분석 타깃에서는 결측 |
| 가격 0 이하 | 검토 후보 | 할인·리워드·조정 코드일 수 있음 |
| 매출 부호 불일치 | 검토 후보 | 가격·수량 양수인데 매출 음수 등 |
| 매출 ÷ (가격×수량) 분포 | 기술 통계 | 원천 집계 방식이 확인되지 않아 크기 차이는 오류로 보지 않음 |

검토 후보는 자동 오류가 아니다. 예를 들어 매출 부호 불일치 행의 상당수는 할인 코드(`OPEN DOLLAR DISCOUNT` 등)다.

## 2. 예측 점검

- 고정 평가 키 대비 예측 누락·중복·초과, 결측, `prediction = max(prediction_raw, 0)` 여부
- 전체·유형·판매량 구간·주 단위 MAE, WAPE, Bias (성능 비교는 0 제한 후 `prediction`)
- 조합별 12주 점검: 기존 규칙 그대로 구현

```
n < 10                                   → insufficient_data
과대예측 주 ≥ 8 그리고 Bias ≥ 0.10        → overprediction_review
과소예측 주 ≥ 8 그리고 Bias ≤ −0.10       → underprediction_review
그 외                                     → not_flagged
```

예측과 실제가 같은 주는 어느 방향에도 세지 않는다. 8주 연속 조건이 아니라 평가된 주 중 8주 이상이다.

지표 정의: MAE = 절대오차 합 ÷ 평가 건수, WAPE = 절대오차 합 ÷ 실제 합, Bias = (예측 합 − 실제 합) ÷ 실제 합. 주 단위 WAPE는 그 주의 여러 조합을 합산한 값이며, 조합·주 한 건의 절대백분율오차와 구분한다. 평가 건수가 0이면 세 지표 모두 NULL, 실제 합이 0이면 WAPE·Bias는 NULL이다.

## 3. Python 대조

| 대상 | 기준 파일 | 비교 |
|---|---|---|
| 그룹 지표 | `final_metrics.csv` | 키 중복 거부·일대일 결합, n 일치, 합계는 상대 1e-12, 비율은 절대 1e-9 |
| 조합별 점검 | `pair_review_flags.csv` | n·과대·과소 주·status 일치, 지표 허용오차 동일 |
| 점검 대상 수 | `review_counts.csv` | 방법별 상태 수 일치 |

결과는 `sql_monitoring/reconciliation.json`에 입력·스크립트 해시, 최대 차이, 라이브러리 버전과 함께 저장한다.

## 직접 실행 확인

보완한 코드로 원천 79,459행과 기존 최종 산출물을 읽어 실행했으며, 종료 코드 0과 `passed: true`를 확인했다.

- 그룹 집계 **54행**(18개 그룹 × 3개 방법), 조합별 점검 **516행**이 Python 결과와 허용오차 이내 일치했다. 54행은 54개 개별 지표가 아니라 집계 결과의 행 수다.
- 최대 절대 차이: WAPE `1.17e-15`, Bias `9.16e-16`, MAE `6.22e-14`, 절대오차 합 `1.31e-10`.
- 전주 과대/과소/자료 부족은 `0/2/10`, 모델은 `7/25/10`으로 일치했다.
- 실행 환경: DuckDB **2.0.0**. 전체 버전과 입력·스크립트 해시는 로컬 `reconciliation.json`에 기록한다.

추가 검증: 집계 키를 중복시키면 일대일 결합이 실패하는지, 원예측이 NULL이면 입력 검사에 잡히는지, 전 매장에서 같은 한 주를 제거해도 10개 매장의 누락이 잡히는지 확인했다. 검증용 변경은 메모리 안에서만 적용했고 원본·예측 파일은 변경하지 않았다.

첨부 초안 대비 보완: 키 중복을 `validate="one_to_one"`로 거부하고, 관측 날짜의 합집합 대신 고정 52주 달력을 사용한다. 원예측 결측·비유한 값과 고정 평가 건수도 검사한다. 모델·예측·판단 규칙은 바꾸지 않았다.

`passed: true`는 Python 대조와 예측 입력 검사가 통과했다는 뜻이다. 원천의 날짜 오류·검토 후보가 0건이라는 의미는 아니다. 원천 점검 결과는 별도로 남긴다.

## 공개 범위

SQL 2개, 실행 스크립트와 문서만 공개한다. 원본·예측·모델·`sql_monitoring/` 결과 폴더·실행 로그는 공개하지 않는다.
