# Sandwich Forecast Diagnostics

미국 퀵서비스 샌드위치 체인의 공개 POS 자료를 이용한 **주간 판매량 예측 및 오류 진단** 프로젝트입니다.

**기간이 바뀌며 편향 방향이 바뀌었고, 사전에 정한 규칙에 따라 전주 기준선 유지를 제안했습니다.**

[평가 설계](docs/METHOD.md) · [AWS S3 재현 절차](docs/S3_REPRODUCTION.md) · [SQL 운영 점검](docs/SQL_MONITORING.md)

## 최종 결과

| 방법 | 최종 WAPE ↓ | 최종 Bias |
|---|---:|---:|
| **전주(지난주) 판매량** | **24.25%** | **−2.43%** |
| 직전 4주 평균 | 34.80% | −6.51% |
| LightGBM | 25.09% | −7.77% |

- **WAPE:** 전체 실제 판매량 대비 절대오차 합의 비율입니다. 낮을수록 좋습니다.
- **Bias:** 전체적으로 많게 예측하면 양수, 적게 예측하면 음수입니다.
- 최종 공통 평가 집합은 **2,027 / 2,064건(98.21%)**입니다.
- 검증에서 선택한 모델이 최종 기간에는 전주 기준선을 넘지 못했습니다. 최종 평가 후, 미리 정한 규칙에 따라 전주 기준선 유지를 제안했습니다.

## 분석 범위와 핵심 관찰

- 9개 매장, 35개 상품 코드, **172개 매장·상품 조합**을 고정했습니다.
- 최초 학습 26주, 검증 14주, 최종 평가 12주로 구분했습니다.
- 검증 기간에는 세 방법 모두 과대예측했으나, 최종 기간에는 모두 과소예측했습니다.
- 전주 기준선의 최근 4주 Bias는 **+5.74%**로 전환됐습니다. 점검 목록은 12주 기준으로 유지하고, 최근 방향 변화는 별도로 보고했습니다.
- 실제 AWS S3에서 저장 모델과 입력을 읽어 **172/172건**을 재현했습니다. 원예측과 0 제한 후 예측의 최대 절대 차이는 모두 **2.842170943040401e-14**로, 허용오차 `1e-9` 이내였습니다. 모든 검사를 통과했고 종료 코드는 `0`입니다.

실제 기업의 발주·재고 정책을 운영하거나 결품·폐기를 줄인 성과를 주장하지 않습니다. 타깃은 POS 상품 코드의 기록 판매수량입니다.

## SQL 운영 점검

DuckDB로 최종 예측을 재집계해 Python 그룹 집계 **54행**과 조합별 점검 **516행**이 일치함을 확인했습니다. 지표는 허용오차 안에서 대조했고 점검 상태와 대상 수는 정확히 일치했습니다. 원천 데이터의 날짜·중복·음수 판매 등도 별도로 점검합니다. 새 모델 실험은 아닙니다. [실행·검증 설명](docs/SQL_MONITORING.md)

## 실행 코드와 기록의 추적 가능성

공개한 Python 스크립트는 보존된 실행 스크립트와 동일한 파일이며, 공개를 위해 코드를 재정렬하거나 포맷을 바꾸지 않았습니다. **해시를 기록한 단계는 산출물의 `script_sha256` 또는 `scripts_sha256`으로 대조할 수 있습니다.**

기준선 평가(04), 모델 검증(05), 최종 평가(07), 최종 진단(09·10)은 기록된 스크립트 해시와 일치함을 확인했습니다. 모든 단계가 같은 이름의 해시 필드를 제공하는 것은 아닙니다.

## 로컬 재현

Python 3.12 환경을 기준으로 합니다. 데이터는 이 저장소에 포함하지 않으므로 [출처](DATA_ATTRIBUTION.md)에서 직접 내려받아야 합니다.

```bash
pip install -r requirements.txt
```

| 순서 | 명령 | 작업 |
|---|---|---|
| 1 | `python 01_audit.py` | 날짜·키·판매수량 검증 |
| 2 | `python 02_classify_review.py` | 상품명 기반 후보 분류표 생성 |
| 3 | `python 03_select_targets.py` | 최초 26주 기준으로 대상 고정 |
| 4 | `python 04_validation_baselines.py` | 기준선 계산 및 검증 공통 키 저장 |
| 5 | `python 05_train_validation.py` | 고정한 두 모델 후보 비교 |
| 6 | `python 06_validation_uncertainty.py` | 탐색적 불확실성 분석 |
| 7 | `python 07_final_evaluation.py` | 최종 키 고정 및 최종 평가 |
| 8 | `python 08_verify_final.py` | 저장 모델·예측·SHAP 검사 |
| 9 | `python 09_final_diagnostics.py` | 최종 진단과 SHAP 극단 사례 선정 |
| 10 | `python 10_high_volume_diagnostic.py` | 고판매량 구간의 사후 진단 |
| 11 | `python 12_sql_monitoring.py` | 고정 예측의 SQL 집계·점검 및 Python 대조 |

02의 분류는 후보 분류입니다. 03은 이 자동 분류와 코드에 고정한 세트 목록으로 대상을 선정하며, 별도의 수작업 CSV를 요구하지 않습니다.

일부 단계는 기존 결과 폴더를 덮어쓰지 않습니다. 위 과정은 원래 실험을 재현하는 절차이며, 이미 본 최종 결과에 맞춰 사양을 바꾸는 과정이 아닙니다. 원본 파일의 SHA256은 [출처 문서](DATA_ATTRIBUTION.md)에 기록했습니다.

S3 재현은 [별도 안내](docs/S3_REPRODUCTION.md)를 따릅니다. 로컬 분석으로 생성한 저장 모델·입력·전체 172개 예측을 사용합니다. 스크립트가 AWS 리소스를 자동 생성하지는 않습니다.

이 저장소에는 코드, 설명 문서, 요약 지표를 포함합니다. 원본·가공 데이터, 입력·예측 CSV, 학습 모델, 실행 로그, 자격증명은 포함하지 않습니다.

- [`07_final_rules.json`](07_final_rules.json): 최종 평가 전에 고정한 선택·오류 수정·점검 규칙

공개 과거 POS 자료의 조건부 분석이므로 신규·저판매량 상품 전체나 실제 수요를 대표하지 않습니다. SHAP은 예측 기여를 설명하며 인과효과가 아닙니다. 원데이터 라이선스는 코드에 자동 적용되지 않으며, 별도 코드 라이선스는 지정하지 않았습니다.
